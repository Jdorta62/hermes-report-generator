## Tarea

Create `notebooks/ingest_collections.ipynb`: given a folder of Markdown
files, ingest them for real with `hermes-ingest-md` into as many Qdrant
collections as the configuration declares, each with its own documents and
its own chunking and embedder. Epic: `.claude/kanban/backlog/6-ingestion-notebook.md`.

1. **Setup cell**: imports, `OFFLINE = os.environ.get("HERMES_INGEST_OFFLINE") == "1"`,
   the repository root (same `find_root` approach as `rag_evaluation.ipynb`),
   the output folder `OUT_DIR` from `HERMES_INGEST_OUT` or
   `notebooks/out/ingest/` (git-ignored by `out/`).
2. **CONFIG cell** (the one place to edit), shaped like:

   ```python
   CONFIG = {
     "corpus_dir": "notebooks/data",
     "qdrant_url": "http://localhost:6333",
     "force": False,                      # rebuild every collection even if unchanged
     "defaults": {
       "ingest": {"max_chunk_size": 1500, "hard_boundary_levels": [1, 2], "strip_frontmatter": True},
       "embedding": {"provider": "ollama", "model": "nomic-embed-text"},
     },
     "collections": {
       "hermes_report_golden_agents": {
         "documents": ["agentes-ia-arquitecturas.md"],
         "ingest": {"max_chunk_size": 800},   # optional, merged over defaults
       },
       "hermes_report_golden_python": {
         "documents": ["fastapi-readme.md", "flask-readme.md", "pydantic-readme.md", "typer-readme.md"],
       },
     },
   }
   ```

   `HERMES_INGEST_CONFIG`, when set, is the path of a JSON file that
   replaces `CONFIG` (so tests and repeat runs need no notebook edit).
   Offline mode overrides `qdrant_url` to `":memory:"`, every embedder to
   `hash`, and `corpus_dir` to `examples/demo/corpus` unless the JSON file
   sets it.
3. **Validation cell**, before touching Qdrant or Ollama, failing with a
   clear Spanish message:
   - at least one collection;
   - every name starts with `hermes_report_` (`hermes_report.store.PREFIX`);
   - every collection has a non-empty `documents` list with no repeats;
   - every document name exists in the folder as loaded by
     `hermes_report.corpus.load_corpus` (exact `source`, relative to
     `corpus_dir`); the error lists the unknown names and the available ones;
   - `ingest` / `embedding` keys are the ones of `IngestConfig` /
     `EmbeddingConfig`.
   Then show a table: collection, number of documents, chunk settings,
   embedder; and the documents of the folder that no collection uses.
4. **Services cell**: online, `check_ollama` for every distinct Ollama
   embedding model; one embedder per distinct embedding config; the Qdrant
   client with `make_client`.
5. **"Antes" snapshot cell** (read-only on every collection): a table of
   every collection Qdrant holds before ingesting: name, points, vector
   size, distance, and whether it is one of the configured ones (and then
   what the plan does with it: create, check for reuse, or rebuild with
   `force`). Collections that are not `hermes_report_*` are listed but
   marked as never touched.
6. **Ingestion cell** with live feedback: for each collection, a `Corpus`
   restricted to its documents (same `dir`), `ingest_corpus` with the
   merged `IngestConfig` and `EmbeddingConfig`, a shared cache in
   `OUT_DIR / "ingest-cache"` and its `progress` callback printing one line
   per document (source, chunks, cached or embedded, seconds) under a header
   line per collection (`[2/3] hermes_report_golden_python: 4 documentos`);
   then `ensure_collection(client, name, ingestion.points, url, force=CONFIG["force"])`
   and one closing line (`creada` / `recreada` / `reutilizada`, points,
   seconds). A failure in one collection is printed with its error and the
   others continue.
7. **Stats cells** (pandas tables, readable without scrolling):
   - per collection: documents, chunks, chunks per document (min / mean /
     max), chunk size in characters and in tokens (`hermes_enrich.tokens`
     default counter) as min / mean / median / max, vector size, embedder,
     chunk settings, cached vs embedded documents, seconds and outcome;
   - per document and collection: chunks, characters, mean chunk size, and
     the document's `heading_path` depth range when the payload has it;
   - the documents of the folder that no collection used.
8. **"Después" snapshot and diff cell**: the same table as "Antes" after
   ingesting, plus a diff per collection: new, rebuilt (points before →
   after), reused unchanged, failed, and untouched; and totals (collections,
   points before and after, documents ingested, chunks embedded vs read
   from cache, total seconds).
9. **Manifest cell**: `OUT_DIR / "collections.json"` with, per
   collection, its documents with their sha256, the resolved chunker and
   embedding settings, the point count, the outcome, the Qdrant URL and the
   timestamp, plus the before/after snapshots; and the list of collection
   names ready to paste into the `collections` key of
   `rag_evaluation.ipynb`.
10. Markdown cells in Spanish explaining each section and how to change the
   configuration; the notebook is stored without outputs.
11. README (Spanish): a short "Cuaderno de ingesta" section: what it does,
   the CONFIG shape, `HERMES_INGEST_CONFIG`, and how to then evaluate the
   collections with `rag_evaluation.ipynb`.

**Acceptance criteria**
- A non-`integration` test runs the notebook with `nbclient` in offline
  mode over `examples/demo/corpus` with two collections that share one
  document and use different `max_chunk_size`, and checks: both
  collections exist in the in-memory client with the expected documents
  (by `payload["source"]`), the smaller chunk size gives more points, and
  `collections.json` matches.
- A second offline run with the same config reuses both collections
  (`reloaded` false); with `force` true it rebuilds them.
- Validation errors (unknown document, name without the prefix, empty
  documents, unknown chunker key) fail in the validation cell, before any
  ingestion.
- An `integration` test, skipped when Ollama or Qdrant are unreachable,
  ingests two small documents of `notebooks/data/` (if present) into a
  `hermes_report_test_*` collection and deletes it afterwards.
- The offline test also checks the feedback: the "Antes" and "Después" tables, the diff (new on the first run, reused on the second, rebuilt with `force`), the stats tables with the expected collections and document counts, and one progress line per document.
- `uv run just check` is green and `just notebook-clean` passes.

**Design decisions:**
- Cell ids (for tests): `s1-code` setup, `s2-code` CONFIG, `s3-code` validation, `s4-code` services, `s5-code` Antes, `s6-code` ingestion, `s7-code`/`s7-documents`/`s7-unused` stats, `s8-code` Después/diff/totals, `s9-code` manifest. State left in the kernel: `CONFIG`, `PLAN`, `BEFORE`/`AFTER` (lists of dicts), `RESULTS` (per collection: outcome creada/recreada/reutilizada/fallida, error, seconds, ingestion, info), `collection_stats`, `document_stats`, `unused_documents`, `diff`, `totals`, `READY`, `manifest`. Cells 5 to 9 can be re-run in the same kernel (a second "run" with the same in-memory client reuses; set `CONFIG["force"] = True` before `s6-code` to rebuild).
- Diff states: `nueva`, `reconstruida`, `reutilizada sin cambios`, `fallida`, `sin tocar` (the last one flags "¡han cambiado!" if a untouched collection changes its points).
- Offline without `HERMES_INGEST_CONFIG` uses two demo collections over `examples/demo/corpus` (`hermes_report_demo_manuales`, `hermes_report_demo_todo`), because the default CONFIG documents do not exist in the demo corpus. With the JSON file, offline only forces `qdrant_url=":memory:"`, embedders to `hash:hash-256`, and `corpus_dir` to the demo unless the JSON sets it.
- Validation also rejects unknown top-level keys, unknown keys inside `defaults` / a collection, non-positive `max_chunk_size`, bad `hard_boundary_levels`, unknown embedding provider; all problems are reported in one `ValueError` (Spanish).
- `force` only rebuilds the collection (`ensure_collection(force=...)`); the per-document cache is still used (not passed to `ingest_corpus`).
- Progress line is `ingest_corpus`'s own message (`source: N chunks (caché|ingerido)`) plus the seconds since the previous line, measured by a small callable class. "ingerido" is the package's wording for "embedded".
- A failed collection is caught with a broad `except Exception`, printed, recorded as `fallida` and listed in the manifest with its error; it is excluded from `READY`.
- "Antes" lists only collections Qdrant holds; configured collections that do not exist yet are announced in a line below (so the table never invents rows).
