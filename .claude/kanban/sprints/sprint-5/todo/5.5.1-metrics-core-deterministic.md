## Tarea

Create the package `src/hermes_report/metrics/` with its core and the four
deterministic metric families. Design §4 (`base`, `judge`, `selection`,
`runner`, `deterministic`), §5 and §7.

1. **`metrics/base.py`**: `METRIC_STATUSES`, `INPUT_FIELDS`, `MetricError`,
   `RankedChunk`, `Citation`, `MetricInput` (with `has()`), `JudgeCall`,
   `MetricServices`, `MetricResult` (with `not_applicable`, `skipped`,
   `failed`, `to_record`) and the `Metric` Protocol (`reg: metric`).
2. **`metrics/judge.py`**: `Claim`, `ClaimVerdict` and `JudgeSession`
   with `ask` (memo by key; a failure is memoised and re-raised;
   every call logged as a `JudgeCall`) and `calls_since`. The higher
   operations (`answer_claims`, `expected_claims`, `verify`,
   `chunk_relevance`) come in 5.5.2; leave them out here.
3. **`metrics/deterministic.py`**: `doc_retrieval`, `evidence_retrieval`,
   `refusal` and `cost`, with the definitions of design §4. Evidence
   matching reuses `Question.reachable` and `normalise` from
   `hermes_report.questions`. Tokens use a `hermes_enrich` `TokenCounter`
   (`MetricServices.counter`).
4. **`metrics/selection.py`**: `METRICS` (registry in design-table
   order, only the families implemented so far), `MetricSelectionError` and
   `MetricSelection.resolve`.
5. **`metrics/runner.py`**: `evaluate_metrics` (never raises:
   `not_applicable`, `skipped`, `error` as in §7) and `aggregate` /
   `ScoreSummary`.
6. **`metrics/__init__.py`** re-exports the public names of design §4
   that exist after this task.
7. `.api` files.

**Acceptance criteria**
- Every deterministic score matches hand-computed values on small fixtures:
  hits at rank 1, at rank k and none; evidence split across two chunks;
  evidence retrieved but not in the context (`budget_loss` > 0); refusal
  and non-refusal questions; chunks without `source`
  (`not_applicable`).
- A metric that raises yields `status="error"` and the next metric still
  runs; a failed `JudgeSession.ask` is not called again for the same key.
- `resolve` honours default-on, `include`, `exclude`, `enabled=False`,
  and rejects unknown names.
- `aggregate` counts `not_applicable`, `skipped` and `errors` apart and
  averages only real values.
- `uv run just check` is green.

## Contexto

**Decisions taken:**
- The selection unit is the family (`doc_retrieval`), not the score.
- Metrics read a neutral `MetricInput`, not `QuestionRecord`, so the
  notebook can use them (the adapter is task 5.5.4).

**Relevant files:**
- `src/hermes_report/questions.py` — `normalise`, `Question.reachable`.
- `src/hermes_report/providers.py` — `JudgeClient`, `ProviderError`.
- `src/hermes_report/record.py` — `MessageRecord`, `message_record`.
- `src/hermes_report/render/question.py` — how the report already builds a `TokenCounter`.

**Constraints (epic 5, all tasks):**
- Design: `.claude/architect/designs/rag-metrics/design.md` (approved); ADRs 0002 and 0003. Follow its names, signatures and formulas.
- No new dependency in the package. The only approved ones are pandas, jupyterlab, ipykernel and nbclient, in the `notebook` dependency group (task 5.5.6 only). No ragas, deepeval, langchain, sacrebleu or rouge-score.
- Metrics are separate signals: they never change the rule verdict, the judge verdict or the exit code of a run.
- Tests never touch José's resources: Qdrant `":memory:"`, `HashEmbedder`, `EchoLLM`, `EchoJudgeClient` or scripted fake judge clients.
- Judge prompts and any text shown to people in Spanish; identifiers, comments and docstrings in English.
- Use only the public API of the Hermes modules (see `.claude/CLAUDE.project.md`).
