## Tarea

Create `notebooks/rag_evaluation.ipynb`, its dependency group, its test
and the README sections. Design §4 ("Notebook") and ADR 0003.

1. **Dependencies**: `uv add --group notebook pandas jupyterlab ipykernel
   nbclient` (approved by José, 2026-10-22). Nothing else.
2. **Notebook**, with the eight sections of the design, each code cell
   commented (what and why) and showing its intermediate result:
   setup; one `CONFIG` dict (collections, embedding, generation, judge,
   `top_k`, `score_threshold`, payload filters, metrics selection,
   dataset path, insufficient message, note); the offline collection;
   dataset loading (JSON array or `{"title", "questions"}`,
   `ground_truth` alias of `expected`); retrieval and generation with
   `qdrant_client` and `hermes_report.providers`; metrics with
   `hermes_report.metrics`; one experiment row per collection; history in
   `history.csv` + `history.jsonl` + `<run_id>-detail.csv`, then reload
   and sort.
3. **Offline mode** with `HERMES_NOTEBOOK_OFFLINE=1`: `HashEmbedder`,
   `EchoLLM`, `EchoJudgeClient`, Qdrant `":memory:"` and the collection
   `hermes_report_notebook_demo` built from `examples/demo/corpus`.
   `HERMES_NOTEBOOK_OUT` sets the output folder (default `notebooks/out/`,
   git-ignored).
4. **README** (Spanish): a "Métricas" section (families, defaults,
   `[metrics]`, `--metric`, `--no-metrics`) and a "Notebook de
   experimentos" section (`uv sync --group notebook`, `uv run jupyter lab`,
   how to change `CONFIG`, where the history goes).
5. A `just` recipe or test that checks the notebook has no stored outputs.

**Acceptance criteria**
- A test (not `integration`) runs the whole notebook with `nbclient` in
  offline mode into `tmp_path`, twice with different `top_k`, and checks
  that `history.csv` has two comparable rows with the required columns.
- An `integration` test runs it against real Ollama and Qdrant over a
  collection of `examples/quijote` and skips when they are unreachable.
- The notebook never creates, deletes or writes a collection that does not
  start with `hermes_report_`.
- The notebook is stored without outputs.
- `uv run just check` is green.

**Design decisions:**
- `default-groups = ["dev", "notebook"]` in `[tool.uv]`: without it a fresh `uv sync` (CI) installs only `dev`, and the required non-integration nbclient test could not run in `just check`. It adds no dependency; if José prefers the group opt-in only, remove that line and have the test `importorskip` (decision for the Commander).
- Writes go through `hermes_report.store.ensure_collection`, which already refuses names without `hermes_report_`; online mode never writes. Note the dispatch text says the notebook "only reads collections that do not start with `hermes_report_`", but the design/acceptance say it never writes outside that prefix and the integration test reads a Quijote collection made by `hermes-report run` (named `hermes_report_...`). I implemented the design: any collection may be read, only `hermes_report_*` is written.
- Environment overrides beyond the two in the task (`HERMES_NOTEBOOK_TOP_K`, `HERMES_NOTEBOOK_COLLECTIONS`, `HERMES_NOTEBOOK_DATASET`, `HERMES_NOTEBOOK_QDRANT_URL`) so the tests can run it twice with different `top_k`, and point the integration run at a Quijote collection, without editing the notebook. They are applied before the offline override (offline wins for collection, models, dataset and URL; `top_k` is kept).
- `CONFIG` gains `qdrant_url` (not in the design list); `judge.provider = None` switches the judge off.
- `config_hash` hashes the whole final `CONFIG` (including `note` and the env overrides), so two runs with different `top_k` get different hashes.
- Context = retrieved chunks in rank order (no enrichment), prompt uses `<source n="N" doc="...">` blocks (the format `EchoLLM` reads); refusal = reply starting with `INSUFFICIENT_CONTEXT` (hardcoded: `hermes_generator.answer.codec` is outside the public API allowed list), answer then replaced by `prompt.insufficient_message`. Citations are derived from `[n]` markers (`citations=None`).
- The notebook finds the repository by walking up from the cwd until `examples/demo/corpus` exists, so the kernel cwd must be inside the repo (the repo root or `notebooks/`); nbclient tests must set `resources={"metadata": {"path": ...}}` accordingly.
- Cells carry fixed ids (`s1-code`, ...) so regenerating the file gives no diff noise.
