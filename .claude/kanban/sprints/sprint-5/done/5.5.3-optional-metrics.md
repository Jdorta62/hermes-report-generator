## Tarea

Add the six opt-in metric families, off by default. Design §4 (`optional`).

1. **`metrics/optional.py`**: `bleu` (BLEU-4, brevity penalty, add-one
   smoothing) and `rouge_l` (LCS F-measure), pure Python over

  accents.

  `JudgeSession` (no extra claim or relevance call when 5.5.2 families run
  too).

**Design decisions:**
- BLEU smoothing: add-one on orders 2..4 only (Lin-Och / Chen-Cherry method 2); unigrams unsmoothed. Reason: with add-one on unigrams too, two disjoint texts would not score 0.0, which the acceptance criteria require. Identical texts still give 1.0 because matched == total. Brevity penalty `exp(1 - r/c)` when the candidate is not longer than the reference; empty side gives 0.0.
- Tokens: `normalise()` then `\w+`, so case, accents and punctuation are ignored. `bleu`/`rouge_l` take token sequences (as in the design); `Bleu`/`RougeL` tokenise.
- ROUGE-L: LCS precision/recall harmonic mean (beta = 1).
- `noise_sensitivity` calls `answer_claims()`, `verify(claims, [expected], "answer_vs_expected")` (same memo key as `answer_correctness`) and `chunk_relevance()` (same memo as `context_precision`); only `verify(..., "answer_vs_retrieved")` is new. A claim counts when the expected answer does not support it, the retrieved chunks do, and every supporting chunk is marked irrelevant. No claims gives 0.0; a refused answer is `not_applicable` (as in `faithfulness`).
- `context_entity_recall`: the entity call goes through `JudgeSession.ask("expected_entities", ...)`; no entities gives `None` (as `context_recall` with no claims); matching is `normalise()` substring over the joined context; an entity that normalises to empty counts as missing. `parse_entities` drops repeated entities.
- `toxicity`/`bias`: 1.0 when flagged else 0.0, reason in `details`. `parse_flag` accepts an empty `reason` (models leave it empty when not flagged) but requires the key and a string; an unknown `kind` or a non-dict reply raises `MetricError`.
- `_judge` and `_result` are duplicated privately in `optional.py` instead of importing the private ones of `judged.py` or widening `base.py`.
- Each family has a single score, so the scores dict order is trivially its declared `scores` order.
- The classes are reachable through `METRICS` and `hermes_report.metrics.optional`; the package root `__init__` is unchanged (the judged classes are not re-exported there either).
- `render.html.METRIC_LABELS` does not exist yet; adding the Spanish labels for these scores belongs to task 5.5.5.

**BLEU choice (add-one on orders 2-4 only): sound.** It is the Lin-Och / Chen-Cherry method 2 (NLTK `method2` skips n=1 the same way), meets "disjoint = 0.0" and "identical = 1.0" (including 1-3 token texts, where the empty higher orders become 1/1), and the partial case matches the hand value (a b c d vs a b c e = 0.1875^0.25 = 0.6580; the cat/mat sentence gives 0.4855 by hand). Note a text sharing one word with otherwise disjoint text still scores > 0 (0.32 for 1 of 4), which is the expected effect of smoothing.

**Edge cases detected without coverage (non-blocking):**
- Performance: `bleu` recomputes `_ngrams(reference, n)` inside the generator for every candidate n-gram, so it is quadratic: 500 tokens 0.08 s, 2000 tokens 1.2 s, 5000 tokens 8.8 s (`rouge_l` is O(n*m): 5000 tokens 2 s). Real answers are short so there is no practical impact and the task has no perf target; hoisting `ref = _ngrams(reference, n)` out of the loop is a one-line fix. Not tested with a timing assertion (flaky).
- `context_entity_recall` matches by plain substring on the normalised context: entity "Ana" is found in "banana" (no word-boundary check). It satisfies the design wording ("is in the normalised context"); left uncovered because the behaviour is by design, but it can overstate recall for short entities.
- Entities differing only in case ("Tajo" / "tajo") are not deduplicated by `parse_entities` (exact repeats only), so they count twice.
- `flag_messages(answer, kind)` with a `kind` outside the Literal raises `KeyError` rather than `MetricError`; unreachable through the families (they hardcode the kind), and `parse_flag` does validate the kind.
- `_judge`/`_result` are duplicated from `judged.py` (maintenance risk only).
- Text metrics score refusal-type answers like any other answer (no `refused` check); undefined by the design.

**Verdict:** PASS — all acceptance criteria verified by tests (BLEU/ROUGE-L hand values and normalisation, noise sensitivity reuses the memoised claims/relevance/answer_vs_expected verdicts with exactly one extra call, none of the six runs unless included), 100% branch coverage on the touched modules, the 9 stale registry tests updated; the findings above are non-blocking.
