**Design decisions:**
- `link-mode = "copy"`: with uv's default hardlinks nltk's `pathsec` refuses its own stopwords file (`st_nlink=2`), so ingestion fails as soon as a paragraph needs sentence splitting (any long Quijote chapter, and the demo with `max_chunk_size = 300`). I added the setting and ran `uv sync --reinstall-package llama-index-core` in the local venv. Other machines/CI get it at their next fresh `uv sync`. It is a uv setting, not a dependency change, but José should confirm.
- `prepare.py` leaves the front matter of each book (dedications, prologues, verses) out and puts the inner-part bold lines ("Tercera parte del ingenioso hidalgo...") right under the heading of the chapter that opens them, so every file starts with `# libro` and `## capítulo`. The playground corpus kept that front matter under the H1; none of the 11 questions needs it. Evidence phrases of all 10 answerable questions were checked to be inside their `documents` files.
- Demo uses `max_chunk_size = 300` so the sections split and "needs neighbouring chunks" is real; the whole demo corpus is 17 chunks.
- `_chunk_count` was reused for the singular; the explorer in JS pluralises by the collection total ("1 de 1 chunk", "1 de 4 chunks").
- `examples/demo/out/` and `.hermes-report-cache/` land next to the run file (paths resolve against the run file), hence the unanchored `out/` ignore.
