## Tarea

Implement the comparison report and `hermes-report compare`. Design §8.

1. **`src/hermes_report/render/compare.py`**: `render_compare(runs:
   Sequence[tuple[str, RunRecord]]) -> str`. Each pair is (a link to that
   run's `report.html`, relative to the comparison file; its record). The
   function is pure and gives byte-identical output for the same input. It
   reuses the assets and helpers of `render/html.py`, so it keeps the same
   look, in Spanish.
   - **Header**: "Comparación de N ejecuciones". The generation time comes
     from the latest `finished_at`, not the clock, for determinism.
   - **Ejecuciones**: one column per run, labelled `A`, `B`, `C`... plus its
     title, `started_at` and a link to its report.
   - **Diferencias de configuración**:
     - flatten each `config` to dotted keys, with lists as JSON text;
     - show only the keys whose values differ between runs, one row per key
       and one column per run;
     - also show the package versions from `environment` that differ;
     - when nothing differs, say so.
   - **Puntuación**: the Resumen tab tiles for each run: right by rules,
     right by judge, failures by type, disagreements and mean seconds per
     question. Reuse the code of task 3.3.1 so the numbers match.
   - **Matriz**:
     - one row per question id, over the union of ids in first-appearance
       order, with the question text taken from the first run that has it;
     - one cell per run with the rule verdict pill, the judge pill and the
       seconds, linking to `<report>#q-<id>`;
     - `—` when a run lacks that question;
     - rows whose rule verdicts differ between runs are highlighted;
     - a filter "solo filas con diferencias", a few lines in `report.js`.
2. **CLI**: `hermes-report compare RUN_JSON [RUN_JSON ...] [--out PATH]`.
   - At least 2 files, else exit 2.
   - The default output is `compare.html` in the current directory.
   - Each link is `os.path.relpath` from the output folder to the
     `report.html` next to each `run.json`, with `/` separators.
   - `RecordError` prints `error: ...` and returns 2.
   - A missing `report.html` still gets its link, and a warning is printed.
3. `.api` files.

**Design decisions:**
- Compare page is two tabs (Resumen / Matriz) built with the existing `page()`; no JSON data blocks, so `report.js` only runs the tab routing plus the filter.
- Puntuación is a table (rows = the Resumen tile labels, one column per run, values from `score_tiles`) rather than a tile block per run.
- Config keys are flattened in first-seen order; strings are shown as they are, everything else as JSON text (`true`, `[1, 2]`); a key missing from a run shows `—` and counts as a difference. Differing package versions are rows `environment.packages.<name>` after the config rows. `--only` is not part of the record's `config`, so a different question set shows in the matrix, not in the differences.
- A matrix row is highlighted (`class="diff"`) when the set of rule verdicts among the runs that HAVE the question has more than one value (a run with no `rules` counts as its own value `None`; a gap is not a verdict, so a gap alone does not highlight). Rows carry `data-q="<id>"`.
- The filter checkbox is rendered `hidden` and shown by the script, so it does not appear without JavaScript. The script guards `getElementById` with try/catch because the minimal DOM in `tests/test_render_run.py` has none.
- Link is `<report>#q-<id>` with the id HTML-escaped but not percent-encoded, as `report.js` compares the raw hash with the tab keys.
- Latest `finished_at` is the string maximum (ISO-8601 from the same machine); `render_compare([])` raises `ValueError`.
- CLI: `argparse` `nargs="+"`; fewer than 2 files prints `error: ...` and returns 2; links are `os.path.relpath(<run dir>/report.html, <out dir>)` as POSIX; a missing `report.html` prints `aviso: no existe <path>; el enlace quedará roto` to stderr and keeps the link; `RecordError` -> `error: ...`, 2; a record with the wrong shape -> `error: algún registro no tiene la forma esperada (...)`, 2.
- Carry-over: `usageSets`, its per-state sets and `bySource` use `Object.create(null)`; `usage[question]` is read only if it is an own property. Deep links without a `chunk` param (the raw section link) call `window.scrollTo(0, 0)` after routing; links with a chunk still scroll to the card.

**Edge cases detected without coverage (non-blocking observations):**
- A directory name with `#`, `?` or `%` makes the CLI link (`relpath`, no percent-encoding) point at the wrong place in a browser; the task text asks for the literal relpath, so left as is. Same for ids with `#`/`?`/space in `report.html#q-<id>` (Manuel listed it).
- A record whose `config` is not a mapping (`null`, `"x"`, `5`) is silently treated as an empty config (exit 0, "no differences") instead of exit 2; `environment: {}` and `questions: {}` are accepted too. `questions: []` is valid. Not pinned by a test because it is lenient rather than wrong.
- `packages: {}` in one run and a full dict in another also yields a stray `environment.packages` row with `{}` vs `—`.
- Values are compared as text, so `5` (int) and `"5"` (str), or `true` and `"true"`, show no difference; the run-file schema prevents it in real records.
- `latest finished_at` is the string maximum: ISO timestamps with different UTC offsets could pick the wrong "latest".
- `--out "   "` (blank, not empty) is accepted and writes a file named `   ` (same as `render`; `run` rejects it).
