## Tarea

Implement `src/hermes_report/evaluate.py`: the rule verdict and the LLM
judge. Both work on records, not on live objects. Design §5.4.

1. Constants: `RULE_VERDICTS: Final` is the tuple of the codes of the
   design §5.4 table, in table order, and `JUDGE_VERDICTS: Final =
   ("correct", "partial", "incorrect")`.
2. `rule_verdict(question: Question, record: QuestionRecord) ->
   RuleRecord`:
   - If `record["error"]` is set, or there is no generation result: verdict
     `error`, every other field `None`.
   - `retrieved` is the texts of `record["retrieval"]["chunks"]`.
     `context` is the piece texts of `record["enrich"]["context"]`.
     `cited` is the texts of the context pieces whose 1-based position is
     the `number` of a citation of the result.
   - `in_retrieval`, `in_context` and `in_cited` are
     `question.reachable("\n".join(...))`, so they are `None` without
     evidence.
   - `retrieved_rank` is the 1-based position of the first retrieved chunk
     whose own text holds all the evidence, or `None`.
   - `expected_docs_retrieved` is `None` without `documents`. Otherwise it
     says whether a retrieved chunk's `metadata["source"]` is in
     `question.documents`.
   - `refused` means the status is `insufficient` or `no_context`.
   - For a `refusal` question: `correct_refusal` when refused, else
     `invented_answer`, with `answer_ok = refused`.
   - For other questions, `answer_ok` is `None` without keywords; else
     `False` when refused, else `question.matches(answer)`. Then:
     - `answer_ok` is True: `correct` if `in_context` is not `False`,
       else `correct_without_evidence`.
     - `answer_ok` is False:
       - `in_context` is False: `budget_failure` if `in_retrieval`, else
         `retrieval_failure`;
       - refused: `generation_refused`;
       - otherwise: `generation_wrong`.
     - `answer_ok` is None: `in_context` False gives the failure pair as
       above; otherwise `unrated`.
3. `judge_messages(question: Question, answer: str, status: str) ->
   tuple[PromptMessage, ...]`, a system and a user message in Spanish:
   - The system message tells the model it is a strict grader. It must
     compare the meaning of the candidate answer with the expected answer,
     not the wording. It replies only with a JSON object `{"verdict":
     "correct" | "partial" | "incorrect", "reason": "<one or two sentences
     in Spanish>"}`.
   - The system message also defines the cases. `partial` means right but
     incomplete, or right with a wrong detail. For a question whose right
     outcome is a refusal, `correct` means the answer says the sources are
     not enough.
   - The user message holds the question, the expected answer, whether a
     refusal is expected, the generator status and the candidate answer,
     each labelled.
4. `judge(question: Question, record: QuestionRecord, client: JudgeClient)
   -> JudgeRecord | None`:
   - It returns `None` when there is no generation result.
   - Otherwise it calls `client.complete_json(judge_messages(...))` and
     times it.
   - It parses a JSON object with `verdict` in `JUDGE_VERDICTS` and
     `reason` as a non-empty `str`. Surrounding whitespace or a code fence
     is tolerated.
   - A reply that cannot be parsed or is invalid gives `verdict=None`,
     `reason=None`, `raw=<text>` and `error="respuesta del juez no válida:
     ..."`.
   - A `ProviderError` gives `raw=None` and `error=str(exc)`.
   - `model = client.model`, and `messages` go through
     `record.message_record`.
5. `evaluate.api` next to the source.
