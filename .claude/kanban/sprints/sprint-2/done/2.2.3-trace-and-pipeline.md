## Tarea

Port the playground tracing and run one question through retrieval,
enrichment and generation, recording every phase. Design §5.3 and §6.

1. **`src/hermes_report/trace.py`**: a port of
   `/home/jose/CT/Hermes/Hermes-Generator/hermes-generator/playground/trace.py`
   (branch `dev`), with the same classes and behaviour:
   - `StoreRead`, `EnrichStep`, `LLMCall` and `Trace`. `Trace` has
     `steps`, `context`, `request`, `outcome` and `llm_calls`.
   - `TracingEnricher`, `TracingStrategy` and `TracingLLM`.
   - The private `_TracingStore`.
   - Imports come from `hermes_core`, `hermes_enrich` and
     `hermes_generator`, public names only.
2. **`src/hermes_report/pipeline.py`**
   - `PipelineContext` (dataclass, not frozen):
     - `config: RunConfig`;
     - `qdrant: QdrantClient`;
     - `collection: str`;
     - `retriever: HermesRetrieval`;
     - `llm: LLMClient`;
     - `token_counter: TokenCounter`.
   - `build_context(config: RunConfig, qdrant: QdrantClient, collection:
     str, embedder: Embedder, llm: LLMClient, token_counter: TokenCounter |
     None = None) -> PipelineContext`. It builds
     `HermesRetrieval(embedder=embedder, qdrant_client=qdrant)`, and uses
     `hermes_enrich.tokens.default_token_counter()` when `token_counter` is
     `None`.
   - `answer_question(question: Question, ctx: PipelineContext) ->
     QuestionRecord`. It never raises for pipeline errors.
     - `query = UserQuery(text=question.question, query_id=question.id)`.
     - **Retrieval.** Call `ctx.retriever.retrieve(query,
       SearchScope(collection_names=[ctx.collection]),
       search_params=VectorialSearchParams(top_k=..., score_threshold=...),
       pipeline_control=PipelineControl(candidate_factor=...))` and time
       it. Record it as `RetrievalRecord`, through
       `record.retrieved_chunk_record` and `searched_query_record`.
     - **Enrichment.** Build `HermesEnrich(ctx.qdrant,
       enrichers={e.name: TracingEnricher(e, trace) for e in
       (NeighborsEnricher(), MergeEnricher(), DocOrderEnricher())},
       token_counter=ctx.token_counter)`. Call `.enrich(query, retrieval,
       context_budget=ContextBudget(max_context_tokens=None if 0 else value,
       max_chunks=...), pipeline_control=EnrichmentControl(enrichments=chain))`
       and time it.
       - Set `trace.context`.
       - Record it as `EnrichRecord`, with `budget` set to
         `{"max_context_tokens", "max_chunks"}` as used. Each `EnrichStep`
         becomes a `StepRecord`: `phase` is `step.phase.name`, and the
         reads go through `chunk_range_record` with `returned` as the
         chunk ids.
     - **Generation.** Build `HermesGenerator(TracingLLM(ctx.llm, trace),
       strategies={"default": TracingStrategy(DefaultStrategy(), trace)},
       default_generation_params=GenerationParams(temperature=...,
       seed=...))` and call `.generate(query, context,
       pipeline_control=GenerationControl(response_format=...,
       response=ResponseOptions(insufficient_message=...) when set else
       ResponseOptions(), include_prompt=True))`, timed.
       - Record it as `GenerationRecord`. `llm_calls` comes from
         `trace.llm_calls`: `params` is `dataclasses.asdict(params)` and
         `reply` the four `LLMReply` fields. `result` is
         `generation_result_record(result)`.
     - **Errors.** An exception in a phase sets `error = f"{type(exc).__name__}:
       {exc}"`.
       - The records of the finished phases are kept.
       - The failing phase's record is kept with what the trace has.
         Enrichment keeps its steps so far, with `context=None`.
         Generation keeps its LLM calls, with `result=None`.
       - Later phases are `None`.
     - `spec = question.to_dict()`, `query_id = question.id`, `seconds` is
       the total, and `rules` and `judge` are `None`. Grading is task 2.2.4.
3. `trace.api` and `pipeline.api` next to the sources.

**Design decisions:**
- Imports use public names only: `ContextChunk`, `EnrichedContext`, `PromptMessage`, `UserQuery`, `Embedder`, `GenerationResult`, `RetrievalResult` from the `hermes_core` root (not `hermes_core.enrichment`/`.generation` as the playground did).
- Each phase helper (`_enrich`, `_generate`) fills its record in a `finally`, so a failing phase keeps its steps / LLM calls (`context=None` / `result=None`) and `seconds` up to the failure. The exception propagates to `answer_question`, which sets `error = "Type: msg"` and leaves the later phases `None`. A retrieval failure leaves all three phases `None`.
- `budget` is `{"max_context_tokens": None if 0 else value, "max_chunks": ...}` as passed to `ContextBudget`; set before anything can fail.
- `HermesEnrich`, `HermesGenerator`, `ContextBudget`, `GenerationControl` are built inside the phase `try`, so invalid config values become a phase error instead of an exception.
- With an empty retrieval the facades short-circuit: the enrich record has no steps, and generation returns `no_context` with no LLM call (seen in the smoke run).
- Task text says the error format is `f"{type(exc).__name__}: {exc}"`; used that.

**Out of scope / pending:**
- `rules` and `judge` stay `None` (task 2.2.4).
- Tests for `trace` and `pipeline` are Carlos's.

**q11 with 0 hits (checked, expected):** `score_threshold` (0.3) is applied by the retriever to the raw cosine `vector_score`, not to the fused `score` (about 0.016). The best q11 chunk scores 0.255 < 0.3, so everything is filtered; without a threshold q11 returns all 4 chunks. Pinned by `test_q11_is_empty_because_the_score_threshold_filters_every_chunk`. It is fragile by construction (0.255 vs 0.3 with HashEmbedder), but deterministic.

**Edge cases detected without coverage (non-blocking):**
- `_generate`'s `context is None` guard: unreachable through `answer_question`; the only caller always sets the context first.
- `UserQuery` does no validation (empty text, `None` id are accepted), so `answer_question` cannot raise there today; if hermes-core ever validates, `UserQuery(...)` is built outside the `try` and would raise. Hardening idea: move it inside.
- A failure in `ctx.retriever` that is not an `Exception` (e.g. `KeyboardInterrupt`) propagates by design; tested only for the LLM.
- The default `TiktokenCounter` may fall back to `CharRatioTokenCounter` offline (hermes-enrich handles it); tests use the char-ratio counter for determinism.
