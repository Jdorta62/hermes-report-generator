## Tarea

Orchestrate a whole run and expose it as `hermes-report run`. Design §9.

1. **`src/hermes_report/runner.py`**
   - `RunError(Exception)`, with a Spanish message.
   - `run(config: RunConfig, progress: Callable[[str], None] = print) ->
     RunOutcome`, where `RunOutcome` is frozen with `record: RunRecord`,
     `folder: Path` and `failed: int` (the questions with `error`). Steps:
     1. `load_corpus`, then `load_questions(config.questions.file,
        corpus.sources)`. An unknown id in `config.only` raises `RunError`
        that lists it. The selected questions keep their file order.
     2. `check_ollama` for every model that will be used, in one call:
        - the embedding model, when `provider == "ollama"`;
        - the generation model, likewise;
        - the judge model, when the judge is enabled and its provider is
          `ollama`.
        This runs before any ingestion.
     3. `make_embedder`, `make_llm`, and `make_judge` when the judge is
        enabled.
     4. `ingest_corpus` (with `force=config.reingest`), `make_client`,
        `collection_name`, `ensure_collection` (with `force`) and
        `read_points`.
     5. `build_context`. Then, per question, `answer_question`, then
        `rules = rule_verdict(...)`, then `judge(...)` when enabled. The
        progress line has the format `"· q01 ¿...(first 60 chars) …
        <rule code> / juez: <verdict or —> (4.2 s)"`.
     6. The `RunRecord`:
        - `environment`: `platform.python_version()`, and the versions of
          `hermes-core`, `hermes-ingest-md`, `hermes-retrieval`,
          `hermes-enrich`, `hermes-generator`, `hermes-report`,
          `qdrant-client` and `ollama` (from `importlib.metadata`, `"?"`
          when missing), plus `ollama_host()` and the Qdrant URL;
        - `corpus`, with `chunks` per document from the ingestion;
        - `ingest`, `collection` and `points`;
        - `config = config.to_dict()`;
        - ISO timestamps with offset.
     7. The output folder is `config.output.dir /
        f"{start:%Y%m%d-%H%M%S}-{slug(title)}"`, with a `-2`, `-3`...
        suffix if it already exists. It holds `run.toml` (`to_toml()`) and
        `run.json` (`write_record`).
   - `ConfigError`, `QuestionsError`, `CorpusError`, `ProviderError`,
     `IngestError` and `StoreError` propagate unchanged.
   - The Qdrant client is always closed.
2. **`src/hermes_report/cli.py`**: `main(argv: list[str] | None = None) ->
   int`, `argparse` with `prog="hermes-report"`, Spanish help.
   - Subcommand `run RUN_TOML`, with the flags `--model`, `--judge-model`,
     `--no-judge`, `--top-k N`, `--budget N`, `--out DIR`, `--only ID`
     (repeatable) and `--reingest`. They map to `Overrides`.
   - An empty `--out ""` is rejected by the CLI (exit 2) before a `Path`
     is built.
   - It prints the folder and the `run.json` path. It returns 0, or 1 when
     a question failed.
   - Every error listed above, plus `RunError`, prints `error: <message>`
     on stderr and returns 2.
   - No subcommand prints the help and returns 2.
3. **`src/hermes_report/__main__.py`** calls `sys.exit(main())`, and
   `pyproject.toml` gains `[project.scripts] hermes-report =
   "hermes_report.cli:main"`.
4. **`config.py` change.** `Overrides(out=Path("."))` is accepted again and
   resolves to the current directory. An empty `--out` is now rejected by
   the CLI instead. Update the `Overrides` docstring. Carry-over from
   1.1.1: Carlos updates `test_dot_out_override_is_rejected_like_an_empty_path`.
5. `.api` files next to the new and changed sources.

**Design decisions:**
- Orchestrator decisions applied: the judge runs only when the record has a generation result and no `error`; any exception other than `ProviderError` escaping `evaluate.judge` is recorded as a `JudgeRecord` (verdict/reason/raw `None`, `model = client.model`, measured `seconds`, `messages` from `judge_messages`, `error = f"{type(exc).__name__}: {exc}"`); a `ProviderError` escaping would propagate (`judge` already turns it into a record). `rule_verdict` is computed for every question record.
- `check_ollama` is called once, only when the list of models is non-empty, and the list is de-duplicated (order: embedding, generation, judge). Offline runs never call it.
- The output folder is created after all questions finish (no empty folders on a failed run); `-2`, `-3`... suffix via `mkdir()` retries. `OSError` while creating it or writing `run.toml` becomes `RunError`; `write_record` failures stay `RecordError`.
- The CLI also catches `RecordError` (not in the task list, but it would otherwise be a traceback) and returns 2 for it.
- `main` catches argparse's `SystemExit` and returns its code (`--help` gives 0, usage errors 2), so it always returns an int. `--out ""` is rejected by an argparse `type` function (exit 2) before a `Path` exists.
- A `1` exit also prints `N pregunta(s) con error` on stderr.
- Progress line: `· q01 <question[:60]> … <rule code> / juez: <verdict or —> (4.2 s)`; the seconds cover answering, rules and judge. Extra progress lines: `· Corpus: N documentos`, the per-document ingestion lines of `ingest_corpus`, and `· Qdrant <url> / <name>: cargada|ya cargada (N puntos)`.
- `RunRecord.schema` is `record.SCHEMA_VERSION`.
