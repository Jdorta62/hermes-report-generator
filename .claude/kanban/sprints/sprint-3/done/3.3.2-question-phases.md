## Tarea

Fill each question tab of `report.html` with every phase of the pipeline,
ported from the playground `_scenario`, plus a generic document map.
Design §7 point 4.

1. In `src/hermes_report/render/run.py` (or a new `render/question.py`),
   each question tab shows, after the header and evaluation card from task
   3.3.1, a **flow** row of chips linking to each section, the **document
   map**, and these sections. Each section is ported from its playground
   function (`playground/report.py`, branch `dev`), reading the record
   instead of live objects:
   - **0 Entrada**:
     - the question;
     - the searched queries with their technique chain;
     - the retrieved chunks in order: label, place, score, vector score
       and a 140-character snippet. The label is `source#chunk_index`, or
       the `chunk_id` when there is no source. The place is the
       `heading_path` joined with ` › `, or the character range.
   - **S Semilla**: the `before` of the first step, or "vacía" when the
     retrieval is empty.
   - **E1…En**: one section per enrichment step (port `_step_section` and
     `_reads`): the Qdrant reads (ranges and returned chunks), the pieces
     after the step, and the new chunks marked.
   - **B Presupuesto**: the last step's `after` against the final context:
     - the limit;
     - tokens and chunks before and after, with the bar;
     - the dropped chunks in order;
     - the final context, headed "EnrichedContext (contrato de hermes-core)".
   - **P Prompt**: the prompt messages of the result, when present.
   - **L LLM** (port `_llm_section`): every call, not only the last, with
     model, parameters, tokens, seconds and the raw reply, or its error.
   - **R Resultado**: the answer (`answer_html`), status, strategy, format,
     enrichments, sources, the citations table (number → chunk labels →
     source) and the whole `GenerationResult` as JSON in a `<details>`.
   - **J Juez**, when the judge ran: the messages sent, the raw reply, the
     verdict and the reason.

   Token counts use `hermes_enrich.tokens.default_token_counter()`, created
   once per render. Its name goes in the header meta line.
2. **Document map**, generic, one row per document:
   - Which rows: the documents that have a retrieved chunk, a chunk added
     by enrichment, or that appear in the question's `documents`. They are
     ordered by source.
   - One cell per `chunk_index` of that document. The indexes come from
     the record's `points`, by `payload["source"]`.
   - Cell classes, ported from `corpus_doc_map` and `BookMap`:
     - `orig` when retrieved, `added` when added, `unused` otherwise;
     - `dropped` when the chunk is in `dropped_chunk_ids`;
     - `cited` when it is in a citation's `chunk_ids`;
     - the row is `expected` when its document is in `documents`.
   - The `title` tooltip is `#index · heading_path · 160-character
     preview`.
   - A legend.
   - With more than 400 chunks in one document the cells use the compact
     `sm` class.
3. Errors: when a phase record is `None` because the run failed earlier,
   the section is left out. A failed phase shows its record and the error
   box.
4. `.api` updates for new or changed sources.

**Design decisions:**
- Chunk label is `source#chunk_index` (full source path, not the stem as in the playground), the `chunk_id` when there is no source; place is the `heading_path` joined with ` › ` or `caracteres a–b`, `—` if neither. Refs inside pieces have no metadata, so label/place come from the record's `points` (point id == chunk_id), with retrieved metadata and refs as fallback for hand-built records.
- Pieces show their text as one block (the record has no per-chunk text, so the playground's coloured segments are not possible); chunk pills keep the orig/added/new/gone look.
- Sections left out: everything when `retrieval` is None; S only with a retrieval (steps -> seed, empty retrieval -> "vacía"); B needs `enrich.context` and at least one step; P/R when no result; J when no judge. A generation record with no calls and no result shows the L section with the question error in the error box; no calls but a result shows "no se llama". L shows every call (h4 "Llamada i de N" when more than one), with the error box for a call without reply.
- Doc map: rows = sources of retrieved chunks, chunks added by enrichment (origin non-empty in any step's `after` or the final context) and `spec.documents`, sorted; cells strictly from `points` (a document without points shows "sin chunks en la colección"). `dropped` = final context's `dropped_chunk_ids` plus the result's; row class `maprow expected` plus "· esperado" text; `sm` above 400 chunks in a document. Tooltip: `#i · heading › path · 160-char preview`.
- Flow chips: one per shown section, including Semilla and Juez.
- Entrada has no "Historial" (the record has no chat history). Snippet ends with `…` only when truncated.
- `render_run` got an optional keyword-only `token_counter` so tests can avoid tiktoken's possible download; documented `Effects: net` (and `io, net` on `write_report`) because `default_token_counter()` may download the encoding.
