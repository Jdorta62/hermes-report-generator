## Tarea

Build the frame of `report.html`: the assets, the shared HTML helpers, the
page with its tabs, the **Resumen** and **Corpus e ingesta** tabs, a header
card per question, and the `render` command. Design §7. The look is the
playground report's. José likes it as it is, so port it, do not redesign
it.

1. **Assets**, as package data, read with `importlib.resources`:
   - `src/hermes_report/render/assets/report.css` is the CSS of `_PAGE` in
     `/home/jose/CT/Hermes/Hermes-Generator/hermes-generator/playground/report.py`
     (branch `dev`), unchanged except where this task needs new classes.
   - `src/hermes_report/render/assets/report.js` is its tab script,
     changed in three ways:
     - the panel class is `panel` with `id="tab-<key>"`;
     - the `localStorage` key is `hermes-report-tab:<title>`;
     - the hash is `#<key>` (for example `#q-q05`, `#resumen`). A hash
       that names a tab wins over the saved tab.
   - Both are inlined into the page (`<style>` and `<script>`), so the HTML
     needs no network.
2. **`src/hermes_report/render/html.py`**: helpers shared by every
   renderer:
   - `esc` (`html.escape`);
   - `section(anchor, step, title, summary, body)` and `chip(anchor,
     title, summary)`, ported from `_section` and the flow chips;
   - `status_pill(code)`;
   - `RULE_LABELS` and `JUDGE_LABELS`: Spanish labels for every code of
     `evaluate.RULE_VERDICTS` and `JUDGE_VERDICTS`, ported from the
     playground verdict texts (for example `retrieval_failure` → `"fallo
     de recuperación"`);
   - `RULE_TONES`: `good`, `meh`, `bad` or `info` per code;
   - `answer_html` (ported);
   - `json_block(value)`, a `<pre class="text json">` of indented JSON;
   - `seconds(value)`, formatted `"4.2 s"`;
   - `page(title, meta, tabs, panels) -> str`, which assembles the
     document.
3. **`src/hermes_report/render/run.py`**: `render_run(record: RunRecord)
   -> str`, a pure function of the record, so the same record always gives
   byte-identical HTML. The header holds the title, then a meta line with:
   - the generation model, and the judge model or "sin juez";
   - the Qdrant URL and collection;
   - `started_at` and the total seconds.

   Tabs, in order:
   - **Resumen** (key `resumen`):
     - score tiles: right by rules, right by judge, retrieval, budget and
       generation failures, rules and judge disagreeing, and mean seconds
       per question;
     - one table row per question: id linking to its tab (`data-goto`),
       question text, rule verdict pill, judge pill, a disagreement mark,
       first evidence rank, seconds;
     - the resolved run file as JSON;
     - the environment: package versions, Ollama host and Qdrant URL.

     Port `overview` from `playground/quijote/view.py`. Rules and judge
     disagree when the rule verdict's tone is `good` and the judge says
     `incorrect`, or the tone is `bad` and the judge says `correct`.
   - **Corpus e ingesta** (key `corpus`):
     - the documents table: source, characters, chunks, cached, seconds;
     - the chunker arguments;
     - the embedding provider, model and dimension;
     - the chunk-size statistics (min, median, max of `payload["chunk_size"]`
       over the points), with a small bar per document;
     - the collection: name, URL, points, vector size, distance, indexes,
       and whether it was reused or reloaded.
   - **Chunks en Qdrant** (key `chunks`): only an empty panel with
     `id="explorer"` in this task (task 3.3.3 fills it).
   - **One tab per question** (key `q-<id>`; titles are compact when there
     are more than 6 questions, as in the playground). In this task each
     one holds its header (title, status, seconds, error box) and the
     evaluation card. That card ports `evaluation_card` and adds the judge:
     verdict, reason, model, error, and the raw reply in a `<details>`.
     Task 3.3.2 adds the phases.
4. **`src/hermes_report/render/__init__.py`** exports `render_run`.
5. **CLI and runner**:
   - `hermes-report render RUN_JSON [--out PATH]` writes `report.html`
     next to `run.json` by default. It prints the path and returns 0;
     `RecordError` returns 2.
   - `hermes-report run` now also writes `report.html` in the run folder

**Design decisions:**
- `status_pill(code, kind="rule")` takes a `kind` (`rule`, `judge`, `generation`) because `correct` is both a rule code and a judge code with different labels. `None` renders a muted dash. `GENERATION_LABELS` (answered, insufficient, no_context, error) feeds the question header pill.
- `section` and `chip` escape their `summary` (plain text); only `body` is caller-escaped HTML. Safer by default than the playground, which took pre-escaped summaries.
- `page(title, meta, tabs, panels)`: `tabs` is `(key, label, hover)` triples and `panels` is `(key, body_html)` pairs; `page` builds the `<section class="panel" id="tab-<key>" data-key="<key>">` wrappers so the convention lives in one place. `meta` is HTML the caller has escaped.
- Right by rules counts tone `good` over the questions whose tone is not `info` (`unrated` is excluded from the denominator, as in the playground). Right by judge counts `correct` over the questions that have a judge record (an errored judge counts as not correct); `—` when there is no judge.
- Tab text in the non-compact case is the question text clipped to 40 characters; hover text is `id · question`.
- `write_report(record, path)` lives in `render/run.py` and raises `RecordError` (message "no se puede escribir"), so the runner and the `render` command share it. `render_run` stays pure.
- `render` also maps `KeyError`/`TypeError`/`AttributeError`/`IndexError`/`ValueError` while rendering a schema-valid but malformed `run.json` to `error: <path>: el registro no tiene la forma esperada (...)`, exit 2, instead of a traceback (`read_record` only checks `schema`).
- The Resumen tab shows the question text, not the expected/answer columns of the playground table (the task lists the columns); the environment card is a label/value grid.

**Out of scope / pending:**
- Phases of each question (task 3.3.2) and the chunk explorer (task 3.3.3): the `chunks` panel only holds `<div id="explorer"></div>`.
- Existing tests that now fail because of the intended behaviour change (Carlos updates them): `tests/test_runner.py::test_folder_layout` (folder now also holds `report.html`) and `tests/test_cli.py::test_run_prints_folder_and_record_and_returns_0` (the last output line is now `Informe: ...`).
