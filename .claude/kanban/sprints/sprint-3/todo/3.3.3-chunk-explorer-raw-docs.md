## Tarea

Show the chunks as they are stored in Qdrant. This means the global
explorer in the **Chunks en Qdrant** tab and, in each question tab, the
**Documentos tocados (crudo)** section. Design §7 points 3 and 4.

1. **Embedded data** (in `render/run.py`). Write two
   `<script type="application/json">` blocks, each once per page:
   - `id="hr-points"`: the record's `points`, with `id`, `payload` and
     `vector`, in record order;
   - `id="hr-usage"`: per question id, the chunk ids that were
     `retrieved`, `added`, `context`, `cited` and `dropped`. Their
     definitions are the ones the document map of task 3.3.2 uses; share
     that code.

   Escape the JSON so that it cannot close the script (`<` as `<`).
   Rendering stays deterministic.
2. **`report.js`**: plain JavaScript, no library.
   - **Explorer** (`#explorer`). It has a document `<select>` ("todos" plus
     each source), a text box that filters text, `chunk_id`, source and
     `heading_path` (case and accents ignored), and a "marcar pregunta"
     `<select>` ("ninguna" plus each question id).
     - It shows `N de M chunks`.
     - It renders pages of 50 cards, with "anterior" and "siguiente"
       buttons.
     - Each card shows:
       - `source`, `#chunk_index`, the `char_start–char_end` range, the
         `heading_path` and the size;
       - the full text in a `<pre>`;
       - a `<details>` with the raw payload as indented JSON, and the
         vector summary (dimension, norm, first values).
     - With a question marked, each card gets the classes and badges of
       its states (`recuperado`, `añadido`, `en contexto`, `citado`,
       `descartado`). A filter "solo usados por la pregunta" appears.
   - **Deep links.** `#chunks?doc=<source>&q=<id>&chunk=<chunk_id>` opens
     the tab with those filters set and scrolls to the card.
     - The `chunk_id` is the point id: ingest-md point ids equal the
       retrieval chunk ids. Verify this in the in-memory run and document
       it.
     - Clicking a document map cell, or a chunk label in any section,
       goes to that deep link.
   - **Documentos tocados (crudo)**. In every question tab, a section
     `id="raw-<question id>"` lists the same documents as the document
     map. For each one, all its chunks in `chunk_index` order are rendered
     by the same card code, with that question's states.
     - It is collapsed per document (`<details>`) and rendered lazily the
       first time it opens.
     - The section has a link to the explorer filtered by that question.
   - Without JavaScript, the explorer panel shows a notice in Spanish.
     The rest of the report stays readable.
3. CSS additions for the cards, badges and pager, in `report.css`, using
   the existing variables (light and dark).
4. `.api` updates.
